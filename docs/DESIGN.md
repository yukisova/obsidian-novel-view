# Novel View 设计说明

本文档说明 Novel View 的模块边界、数据格式和主要流程。当前版本为 `0.13.1`。

## 一、设计目标

Novel View 把长篇小说写作所需的几个环节组合起来：

- 用小说组组织整部作品；
- 用卷和章节组织正文；
- 用设定组、标签和记录管理资料；
- 用文字标记追踪伏笔、线索和人物；
- 用查找替换维护一致性；
- 用统计和状态辅助修订。

设计原则：

1. 数据存放在普通 Markdown 文件和少量 JSON 文件中，避免锁定格式；
2. 纯数据逻辑放在 `core`，界面逻辑放在 `features`；
3. 视图不直接依赖其他视图；
4. 旧数据尽可能兼容，不因升级丢失；
5. 自动保存，失败时明确提示。

## 三、小说组

小说组是一个普通文件夹，至少包含一个 `novel.json`。

示例：

```json
{
  "novel-description": "",
  "novel-cover": "",
  "volume-order": [],
  "volumes": {},
  "article-groups": [],
  "history": []
}
```

小说组根目录下的卷就是子文件夹。文章是卷中的 Markdown 文件，也可以直接放在小说组根目录。

### 小说组入口

- 文件树右击文件夹：构建小说组；
- 工作台：小说简介、封面、状态；
- 文章列表：左栏展示卷和章节；
- 设定组列表：左栏展示设定资料；
- 文字标记：右栏展示标记。

## 四、文章列表

文章列表由 `NovelArticleListView` 负责。

数据来源：

- 小说组配置；
- 卷文件夹；
- 章节 Markdown 文件；
- 卷顺序；
- 文章组配置。

主要功能：

- 新建卷、新建章节；
- 拖动章节到卷；
- 卷排序；
- 章节状态和字数；
- 对照组数量；
- 多选、框选、右键菜单；
- TXT 导入导出入口。

## 五、小说编辑器

编辑器由 `NovelEditorView` 提供，使用 CodeMirror。

`NovelEditorView` 是独立视图类型，不是 MarkdownView 的模式。

小说组章节的打开路径仍然进入 NovelEditor：

- 文件树、快速切换器打开小说章节时，路由到已有的 NovelEditor 标签；
- 如尚无 NovelEditor，则把当前 Markdown 标签转换为 NovelEditor；
- 普通非小说 Markdown 不进入 NovelEditor。

隐藏 `.view-header`；标签和正文标题都使用当前章节名。

打开时优先复用已有 NovelEditor 标签，否则新建标签。

主要特征：

- 打字模式；
- 小说排版样式；
- 关键词高亮；
- 文字标记；
- 对照组代码块；
- 状态角标；
- 目录导航；
- 自动保存。

正文数据仍在 Markdown 文件中。编辑器只增加显示层与交互层，不改变 Markdown 的基本格式。

### 编辑器模式

编辑器工具栏支持多选模式：

- 打字模式：当前编辑行保持在视口中央；
- 纯粹模式：隐藏 Obsidian 标签栏和左右侧栏；
- 黑屋模式：限时全屏，阻止 Obsidian 内部页面切换；


### 无缝模式

无缝模式在同一个 `NovelEditorView` 内工作，不切换标签页。

- 以当前章节为中心，加载前后各 N 章，默认 N=1；
- 章节按小说组文章顺序排列；
- 章节正文直接拼接到 CodeMirror 文档，不写分隔标记到原文；
- 章节边界由 `StateField` + `Decoration.widget` 渲染，只显示章节标题；
- 文档变更通过区间映射表按章节写回，只有发生修改的章节文件会被保存；
- 跨章节边界的删除/替换被 `transactionFilter` 拦截；
- 滚动到顶部或底部时自动加载上一章或下一章；
- 以视口中心章节为窗口中心，最多同时保留 5 章；
- 超出窗口的远章节在保存后从编辑器和 section 列表中卸载；
- 卸载时按屏幕锚点校正滚动位置；
- 无缝模式隐藏滚动条；
- 每个章节区间的首个非空正文行强制应用首段缩进与正文段落装饰；
- 滚动加载使用防抖，避免频繁读取；
- 切换模式、切换章节、关闭视图前会先保存；
- 黑屋模式激活后单击一次打开退出确认，取消保持、确认退出；
- 无缝窗口加载/卸载期间暂停打字模式自动居中，避免滚动回滚；
- 格式设置卡片锚定在格式设置按钮上方；
- 页边距使用“自动适应”复选框，勾选时隐藏字符宽度控件。

### 界面布局

- 底部工具栏只保留编辑动作：自动排版、查找、插入图片、格式设置；
- 打字、纯粹、黑屋、无缝四个模式按钮放在右下角的横向模式栏；
- 文章信息顶部只显示当前章节名，下方用分隔线分隔各内容区。



前后章数量配置项：

```text
localStorage["novelview:seamless-neighbors"]
```

默认 1，范围 0–3。

### 页边距与光标

页边距设置保存在浏览器本地存储中：

- 自动适应：不限制每行字符数；
- 固定字符宽度：限制正文最大宽度。

编辑器按章节记录最近一次光标位置，重新打开时恢复。

### 脚注与引用块

正文中保存脚注引用：

```text
[^1]
```

编辑器中显示为脚注序号 `1`，不显示 `[^1]`。

脚注说明不写入文章末尾，而是保存在浏览器本地存储中，由文章信息侧栏显示。

插入脚注后，文章信息侧栏会显示对应的内联输入框，用户直接填写说明；点击正文脚注序号会聚焦该输入框。

引用块使用 `>` 行首标记。编辑器为引用行增加独立背景、左边框、较小字号和更紧凑段距。

### 文章信息侧栏

文章信息视图类型为 `novelview-article-info`，固定展示在主区域右侧。

打开 NovelEditor 时自动切换到对应章节，并每 500 毫秒比较一次快照。

使用普通分区和分隔线，不再使用卡片外框：

- 内容摘要：用户自行填写，输入框不包卡片；
- 字数；
- 文字标记：有数据时才显示；
- 对照组：有数据时才显示；
- 脚注：有数据时才显示，标题固定为“脚注”，说明使用内联输入框编辑。

顶部只显示当前章节标题和分隔线。

## 六、文字标记

文字标记保存在文章属性中，属性名为 `novelview-marks`。每个标记包含：

```json
{
  "start": 0,
  "end": 10,
  "label": "标记名称"
}
```

`start` 和 `end` 是正文偏移，不包含属性区。

### 标记名称与说明

标记名称是聚合单位。同名标记会显示在同一张卡片中。

说明保存在小说组的：

```text
novelview-mark-notes.json
```

结构：

```json
{
  "标记名称": "说明内容"
}
```

### 标记顺序

同一标记名称内的展示顺序保存在：

```text
novelview-mark-order.json
```

结构：

```json
{
  "标记名称": ["文件路径\u0000开始\u0000结束"]
}
```

### 标记卡片

- 默认折叠；
- 点击标题展开；
- 展开后显示说明和所有片段；
- 搜索只匹配标记标题；
- 卡片可拖动重排；
- 拖动到其他标记标题可更换归属。

## 七、设定组

设定组是小说组下的 `-` 前缀文件夹。

每个设定组包含 `index.md`，用于保存标签和记录。索引包含：

- 标签名称；
- 标签颜色；
- 记录关键词；
- 记录内容；
- 字段；
- 标记区间。

设定组列表由 `NovelSettingListView` 负责，设定详情由 `SettingCollectionView` 负责。

### 展示规则

- 标签标题可折叠/展开；
- 记录以卡片形式显示；
- 搜索只匹配设定记录名称；
- 记录可拖动排序；
- 详细设定文件为 `.d.md`，用原生 Markdown 视图打开。

## 八、详细设定文件

以 `.d.md` 结尾的文件视为详细设定文件。

规则：

- 不进入普通文章列表；
- 在设定组列表中单独列出；
- 点击使用 Obsidian 原生 Markdown 视图打开；
- 显示名称去掉 `.d.md` 后缀；
- 默认新建名称为 `设定.d.md`。

## 九、查找与替换

查找支持：

- 当前章节；
- 本卷；
- 全书；
- 文字标记；
- 对照组；
- 关键词。

选项：

- 区分大小写；
- 全词匹配；
- 正则表达式。

替换前会扫描匹配，结果过多时阻止批量替换，避免误操作。

## 十、对照组

对照组用于标记需要比较、修改或保留的段落。

格式：

````markdown
```对照组🟢
内容
```
````

兼容旧名称：

````markdown
```待修改部分🟢
内容
```
````

新写入统一使用“对照组”。文章列表会在字数旁显示绿色数量徽章。

## 十一、首次安装与更新说明

模块：`src/app/onboarding.ts`

文档：

```text
docs/onboarding/INTRODUCE.cn.md
docs/onboarding/INTRODUCE.en.md
docs/onboarding/UPDATED.cn.md
docs/onboarding/UPDATED.en.md
```

规则：

- 首次安装显示介绍；
- 版本变化显示更新说明；
- 同版本只显示一次；
- 中文系统使用 `.cn.md`；
- 其他语言使用 `.en.md`；
- 使用 Obsidian Markdown 渲染器显示。

状态保存在浏览器本地存储中，避免修改小说数据。

## 十三、设置

插件不注册独立设置页。

写作格式设置通过编辑器工具栏中的格式面板调整。

## 十四、构建与部署

```bash
npm run check
npm test
npm run build
```

构建流程：

1. `tsc --noEmit` 类型检查；
2. esbuild 打包 `src/main.ts`；
3. Markdown 说明文档作为文本打包；
4. 部署到 Obsidian 插件目录。

安装包只包含：

```text
main.js
manifest.json
styles.css
```

## 十五、开发约定

- 新功能优先放入 `features`；
- 数据模型和纯函数放入 `core`；
- 编辑器扩展放入 `editor`；
- 通用弹窗和组件放入 `ui`；
- 视图不直接操作另一个视图的 DOM；
- 修改数据后通过插件方法刷新相关视图；
- 不删除用户已有数据；
- 新增兼容逻辑要有明确迁移路径；
- 每次改动执行类型检查和测试。
