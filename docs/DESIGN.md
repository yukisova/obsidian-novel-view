# Novel View 0.7.21 设计说明

## 1. 数据与状态

- 小说组：非根目录文件夹 + `novel.json`。
- 文章：小说组内普通 Markdown。
- 章节状态属性：`novelview-state`，值支持 待写/草稿/大纲/修改中/已完稿（及英文别名）。
- 小说状态 `novelstate` 已删除；加载时清理旧属性。
- 描述 `描述` 属性、卷描述正文、浮动描述面板全部删除；加载时清理。

## 2. 文章列表

- 标题只显示小说名 + 正文数量。
- 左侧替换文件列表；标题栏返回图标；工具栏可见“返回”按钮。
- 章节行显示字数 + 状态。
- 多选：框选/Shift/Ctrl；多选禁止重命名。
- 右键：重命名（单选）、删除（批量）；无编辑描述。
- 新文章“无标题”，frontmatter 只写 `novelview-state: 待写`。
- 新卷“无名卷”，重名编号。

## 3. 小说模式状态卡

- 右上角状态卡显示字数 + 章节状态。
- 点击弹出状态菜单，写入 `novelview-state`。
- 状态改变后刷新文章列表和编辑器状态卡。
- 不再打开小说信息。

## 4. 小说组点击

- 点击小说组：打开/聚焦左侧文章列表。
- 若主区域已存在工作台：只更新 `workbenchFolderPath` 并刷新，不自动跳转。
- 若不存在：打开工作台。

## 5. 联动库

### 5.1 存储

- 配置文件：`<novel-group>/links.json`（不再使用 `link/` 文件夹）。
- 结构：

```json
{
  "group": { "联动组1": "#aa3311" },
  "link": [
    { "未命名.md": { "belong": "联动组1", "alias": ["你好"] } },
    { "~/仓库内引用.md": { "alias": ["你好hk"] } }
  ]
}
```

- 读取时清理目标文件已不存在的记录。
- 导入候选：仓库内任意 TFile，只要不属于小说组；支持非 Markdown 和插件文件。
- 路径：`~/` 仓库根；裸路径按当前卷、组根、旧 `link/` 回退。

### 5.2 UI

- 标题 + 分隔线 + 工具栏，样式与素材库一致。
- 无顶部工具栏；右键空白：新增联动组、导入联动文件。
- 组可展开/折叠；组不可嵌套；组/文件可拖拽、聚焦。
- 右键组/文件：编辑、重命名、删除。
- 重命名：行内输入。
- 编辑：无遮罩浮动面板；组只改颜色，文件只改别名，不弹对话框。
- 导入：悬浮树窗口，显示路径，可设置别名，Enter 依次确认。

## 6. 素材库

- 标题 + 分隔线；单图标。
- 空状态水印：“双击空白区域可导入图片”。
- 双击空白选择图片，写入 `<group>/src/`。
- 卡片提供“重命名”按钮，行内编辑；无卡片右键菜单。
- 打开/删除；无复制链接。

## 7. 链接关键词

- 沿用联动库 JSON 的 group/link 数据。
- 关键词：文件名去 `.md` + alias。
- 颜色来自 group；缺 belong 归默认组。
- `~/` 从仓库根解析；裸路径支持当前卷/组根/旧 link 文件夹。
- 编辑/阅读视图高亮，点击打开目标。

## 8. 清理

- 特殊页面（设定/人物/时间线/伏笔/大纲/灵感）全部移除。
- 旧 `novelview-type` 分类属性清理。
- 描述属性/正文清理。
- 小说状态属性清理。

## 15. 0.7.21 渲染问题排查

- 现象：文章列表/文件列表切换时，左侧 Ribbon 偶尔被黑色背景覆盖，毛玻璃失效。
- 原因：自定义文章列表叶子叠加了 `contain: paint`、`isolation: isolate`、`z-index`，并额外覆盖了 workspace leaf/header 背景，形成额外合成层；Electron/Chromium 在 backdrop-filter 毛玻璃层与新合成层交叉时出现黑色 tile。
- 处理：移除 contain/isolation/position/z-index 与 leaf/header 背景覆盖；文章列表只保留单一不透明内容背景。
- 同时移除文章状态卡、浮动工具栏、TOC 的 backdrop-filter，改用不透明背景，避免额外 GPU 层。

## 34. 0.7.21 联动关键词唯一性

- 关键词按不区分大小写去重，保证一个关键词只对应一个联动文件。
- 编辑别名时校验与已有文件名/别名冲突，冲突拒绝保存。
- 重命名、导入继续强制唯一别名。


## 35. 0.7.21 关键词唯一指向

- 导入、别名编辑、文件重命名统一使用有效关键词做冲突检查。
- 别名编辑冲突时弹出强制别名窗口；取消则不保存任何修改。
- 重命名冲突时别名只替代显示关键词，不再修改实际文件名，避免产生两个同名文件。
- 解析 links.json 时按路径去重，避免同一文件出现两条记录。
- 关键词表仍按大小写不敏感去重，保证一个关键词只指向一个文件。

- 框选缩小时之前命中但已不在框内的项目会被取消选中。


## 38. 0.7.21 文章组连续性与重命名

- 文章组路径在文章重命名后自动替换为新路径。
- 底层统一执行文章组规范化：
  - 仅保留同卷内连续的文章；
  - 不连续路径拆分为连续段；
  - 少于两篇的段移除；
  - 重叠成员只归属一个组。
- 重命名、删除、移动、拖拽排序、加入组、移出组后都会触发规范化。


## 39. 0.7.21 关键词卡片与去重

- 移除联动组字体样式数据、编辑 UI、列表展示和关键词样式类。
- 关键词悬停卡片显示文件名、标签、联动组；鼠标离开或滚动时关闭。
- 阅读视图与编辑器共用同一关键词信息属性。
- 同一章节内每个关键词只高亮第一次出现，编辑视图按整篇文档去重。


## 40. 0.7.21 联动编辑拆分、卷新建与 MainArea 拖拽

- 联动文件右键拆分为“编辑别名”和“归入标签”；别名行内编辑，标签卡片自动聚焦并支持回车，空值用“标签”。
- 卷右键新增“新建文章”。
- 文章拖拽到 MainArea 三种目标：空白内容第二栏、标签页栏追加、标签页标题替换并追加其余。
- 拖拽浮动卡片实时显示文件数和目标操作；Esc/拖出取消。
- 关键词悬停卡片改为定位在关键词首字下方。


## 41. 0.7.21 MainArea 拖放修复

- 拖放处理器改为捕获阶段监听，避免 Obsidian 标签页/编辑器先消费 drop 事件。
- drop 时先复制路径再清理缓存，并从 DataTransfer 兜底读取 JSON。
- dragend 延迟清理，避免先于 drop 清空拖拽上下文。
- 打开异常会记录日志并提示。


## 42. 0.7.21 拖放兜底

- 拖拽监听提升到 window 捕获阶段。
- 记录最后一次有效悬停的目标模式与目标标签页。
- drop 未触发时，dragend 使用最后一次有效上下文执行一次兜底打开。
- 拖拽路径在 drop 前复制，并从 DataTransfer 兜底恢复。
- 源列表不再提前清理拖拽上下文。


## 43. 0.7.21 恢复文章列表拖拽

- 根因：同一拖拽先经过 MainArea 后再回到文章列表时，窗口捕获的 drop 仍持有 MainArea 模式，阻止了列表内部 drop。
- 窗口拖放处理显式忽略文章列表区域，交还给列表自身。
- 新拖拽开始时重置上一次的 MainArea 目标模式。


## 44. 0.7.21 原生文件拖拽与文章拖拽隔离

- 原生文件浏览器拖拽不再命中文章拖拽处理器。
- 文章拖拽处理器要求 DataTransfer 同时带有文章自定义 MIME 和内部路径缓存。
- 非文章列表区域开始 dragstart 时清理残留的文章拖拽状态。
- 原生文件可正常拖入 MainArea，文章拖拽三种目标保持独立。


## 45. 0.7.21 静态样式规范

- 所有 `element.style.*` 直接赋值改为 Obsidian 的 `setCssStyles` / `setCssProps`。
- 覆盖拖拽提示、卷/文章组悬停卡片、框选框、查找窗口拖动和浮动子菜单。
